## 2025-03-05 - Caching and Firestore `in` Batched Queries for Backend Functions
**Learning:** Sequential Firestore queries in a `for` loop (like the N+1 query in `build_syllabus_context`) can cause significant cold-start delays. Firestore limits `in` queries to 30 items. A thread-safe TTL cache efficiently resolves this, but iterating the initial ID list while holding a lock prevents race conditions on cache eviction. Furthermore, the mock `_FakeDB.where` used in testing needs an explicit implementation to handle `in` lists for any tests using it.
**Action:** Next time an N+1 query is seen, batch it with `in` queries chunked by 30, implement a thread-safe dict cache with TTL, cache empty hits for missing keys to prevent duplicate failing fetches, and ensure `_FakeDB.where` supports `op == 'in'` in the tests.
