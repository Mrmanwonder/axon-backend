## 2024-05-24 - Firestore N+1 Batching Optimization
**Learning:** Sequential `.get()` queries on Firestore inside a loop for specific keys result in severe cold-start latency due to N+1 query patterns. This often surfaces in backend endpoints that iteratively fetch related metadata (like `build_syllabus_context` fetching mapping docs per learning objective). Caching whole collections to avoid this is an anti-pattern causing OOM. The ideal fix combines a thread-safe TTL cache with a batched query using Firestore's `in` operator (chunked to limits of 30), and carefully caching negative 'not found' results to prevent repeat misses from bottlenecking.
**Action:** When replacing `for id in ids: get(id)` patterns with `in` operator batching, ensure to cache successful misses and chunk queries to max 30 to comply with Firestore limits.
