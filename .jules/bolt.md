## 2025-05-23 - Thread-Safe Batch Caching for Firestore N+1 Queries
**Learning:** Resolving N+1 Firestore `.get()` queries sequentially blocks network I/O and causes performance degradation. By replacing sequential loops with a thread-safe in-memory TTL cache and batched queries via the `in` operator (chunked to Firestore's limit of 30), database latency and connection usage can be significantly reduced. Re-ordering of native results needs to be explicitly maintained by iterating over requested IDs. Failed batch requests must not poison the cache with negative values.
**Action:** When implementing caching and batch fetches for N+1 problems in this project's serverless backend environment, use `threading.Lock()`, dictionary de-duplication, chunk requests to $\le30$ keys, explicitly reconstruct sequence output ordering, and ignore caching of missing values during failures to prevent cache poisoning.
