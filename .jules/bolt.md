
## 2024-05-24 - Firestore N+1 Query Cold-Start Anti-Pattern in Serverless Environments
**Learning:** In the FastAPI serverless backend, fetching static collections (like syllabus descriptions) iteratively causes severe N+1 query bottlenecks and cold-start latency. Retrieving the entire collection into memory upfront is also dangerous due to OOM errors and memory limits. Attempting to use Python's multiprocessing or concurrent.futures in serverless contexts often exacerbates the issue by exceeding thread budgets or violating runtime sandboxes.
**Action:** Implemented a size-bounded, in-memory TTL cache (`_SYLLABUS_CONTEXT_CACHE`) secured by a `threading.Lock`. The cache logic explicitly deduplicates IDs, isolates cache reading/writing to avoid race conditions during eviction, and batches network lookups using Firestore's `in` operator (chunked to limits of 30). Crucially, failed lookups (non-existent IDs) are cached with empty strings to prevent repeated N+1 misses, while preserving determinism when reconstructing the final results list.
