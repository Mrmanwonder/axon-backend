## 2024-05-24 - Batching Firestore Queries & In-Memory TTL Caching
**Learning:** Replacing an N+1 Firestore `.get()` loop with an `in` operator (batch size up to 30) combined with an in-memory TTL cache using `threading.Lock` significantly improves performance, but it's crucial to map the fetched results correctly and cache "not found" entries (e.g. as empty strings) to prevent re-querying missing data repeatedly. Also, when reconstructing the final list of items, iterate over the original requested list rather than the batched result to ensure the ordering is preserved deterministically. Finally, ensure all necessary standard library modules like `time` and `threading` are imported at the top level to avoid runtime `NameError` exceptions which tests might miss if not specifically invoking the newly optimized code path.
**Action:** Always map batched results to ensure deterministic ordering when reconstructing final outputs, cache missing items ("not found") using sentinel values (like empty strings) for efficiency, and strictly double-check top-level Python standard library imports are complete.
