## 2024-05-19 - Fast batched fetching in Firestore with memory cache
**Learning:** Single document fetches in loops (`N+1` queries) in Python backends (like `FastAPI`) are extremely slow with Firestore and block execution, risking OOM and cold-start latency. Simple TTL-based in-memory caching requires locks and careful handling of database misses so they don't poison the cache. Also, `functions/requirements.txt` should never be recreated from scratch blindly or saved with `pip freeze`, as Windows/Powershell environments might save it in UTF-16, rendering it corrupt on CI.
**Action:** Always batch Firestore fetches using `in` queries (up to limit 30 per query) and lock memory caches to stay thread-safe without dropping fallback error handling. When modifying python code, manually ensure comments for performance PRs are added, rather than skipping the step. And strictly avoid modifying `requirements.txt` unless you specifically add a package.
