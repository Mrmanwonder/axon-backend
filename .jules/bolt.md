## 2024-07-26 - Thread-Safe TTL Caching for Firestore Collections
**Learning:** In the serverless Python backend, fetching entire static collections (e.g., `syllabus_maps_collection().get()`) into memory or performing repetitive single-document fetches causes severe cold-start latency and N+1 query bottlenecks. Caching must be thread-safe (using `threading.Lock`) and properly handle missing keys to prevent cache poisoning or repeated network I/O for non-existent documents. Firestore's `in` operator allows efficient batching up to 30 items.
**Action:** When implementing in-memory caching for batched queries, use chunked `in` queries (limit 30) for specific missing keys. Ensure locks do not block network I/O, cache missing keys (e.g., using empty strings), and reconstruct final output iteratively to preserve deterministic ordering.
